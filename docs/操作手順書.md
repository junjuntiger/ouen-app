# 操作手順書

**プロジェクト名：** shinEDO-ouen（OUEN-APP）
**作成日：** 2026-08-17

---

## 1. 一般ユーザー向け操作手順

### 1-1. 新規登録

1. アプリを開く（ログイン画面）
2. 「新規登録」タブを選択
3. メールアドレスとパスワード（6文字以上）を入力し「登録する」をタップ
4. 「確認メールを送信しました」と表示された場合は、届いたメール内のリンクをクリックして確認を完了する
   - Supabase側の設定によっては確認不要ですぐログインできる場合もある
5. 「ログイン」タブに戻り、同じメールアドレス・パスワードでログイン

### 1-2. プロフィール設定（初回ログイン時のみ）

1. お名前を入力（必須）
2. 職業・活動、地域、ひとことを任意で入力
3. 定価メニューを1件以上登録（商品・サービス名と金額）。「＋メニューを追加」で複数登録可能
4. 「プロフィールを登録する」をタップするとホーム画面に進む

### 1-3. おーえんする（応援を送る）

1. 画面下部ナビの「おーえん」をタップ
2. **Step1**：応援したいメンバーを検索して選択（自分自身は候補に出ない）
3. **Step2**：相手の定価メニューから選択し、数量・支払い金額を入力（支払いは定価以上が必須）。リストにないものは「その他」から自由入力で追加可能。メッセージは任意
4. **Step3**：内容を確認し「おーえんする！」をタップ
5. この時点ではまだ「確認待ち」の状態で、OPはまだ加算されていない。支払額が定価を上回った差額分は、相手が受け取りを確認すると加算される（1-5参照）

### 1-4. メンバー一覧の見方

- 検索バーで名前・職業・地域・ひとことから絞り込み可能
- 各メンバーカードの「おーえん」ボタンから、そのメンバーが選択済みの状態でおーえん画面に直接進める

### 1-5. マイページ

- **取引履歴タブ**：支払い／受取、期間（今月・先月・先々月・その前・全て）で絞り込み可能
- 自分が**受け取る側**の取引が「確認待ち」の場合、その取引に「**受け取りました**」ボタンが表示される。実際に応援を受け取ったらこれをタップすると、その場でOPが加算される（確認するまでOPは増えない）
- **プロフィール編集タブ**：
  - 「写真を変更」ボタンから画像を選択するとプロフィール写真を設定できる（5MB以内の画像ファイルのみ）
  - 名前・職業・地域・ひとこと・定価メニューを編集し「保存する」
- 画面下部の「ログアウト」ボタンでログアウト

## 2. 管理者向け操作手順

### 2-1. 管理者権限の付与

管理画面から直接付与できる（Supabaseダッシュボードを開く必要はない）。

1. マイページ → 「管理画面へ」→ **ユーザータブ**
2. 対象ユーザーの行の「管理者にする」ボタンをタップ（確認ダイアログが出るので「OK」）
3. 対象ユーザーがアプリを再読み込みすると、マイページに「管理画面へ」ボタンが表示される
4. 管理者権限を外す場合は、同じボタン（「✓ 管理者」表示）をもう一度タップする

> 一番最初の管理者だけは、上記の方法が使えない（誰も管理画面に入れないため）。その場合のみ、Supabaseダッシュボード → Table Editor → `profiles`テーブルで対象ユーザーの`is_admin`列を直接`true`に変更する。

### 2-2. 管理画面の使い方

1. マイページ → 「管理画面へ」をタップ
2. **統計タブ**：総ユーザー数・総取引件数・総売上・総発行OPを確認できる
3. **ユーザータブ**：名前・メールアドレス・職業・地域・OP・登録日の一覧。OP残高部分（✏️アイコン）をクリックすると数値を直接編集できる。「CSVダウンロード」で一覧をCSV保存できる
4. **取引履歴タブ**：各行に状態（確認待ち／受取済）を表示。「削除」ボタンで取引を削除できる（確認ダイアログあり。削除してもOPは自動的には戻らないため、必要ならユーザータブでOPも合わせて修正する）

## 3. 開発者・運用者向け操作手順

### 3-1. ローカル開発環境の起動

```bash
npm install
npm run dev
```

`.env`に以下を設定しておく（`.env.example`参照）：

```
VITE_SUPABASE_URL=（SupabaseプロジェクトのURL）
VITE_SUPABASE_ANON_KEY=（Publishable/Anonキー）
```

起動後、ブラウザで http://localhost:5173 を開く。

### 3-2. Supabaseスキーマの適用（新しいSupabaseプロジェクトの場合）

1. Supabaseダッシュボード → **SQL Editor**
2. `supabase/schema.sql`の内容を貼り付けて実行（テーブル・RLS・RPC関数・Storageバケットを作成。この時点で確認フロー・管理者用メール取得関数も含まれる）

> 既に`schema.sql`を適用済みの環境に新しいマイグレーションファイル（`migration_002_avatar.sql`、`migration_003_admin_email.sql`、`migration_004_confirmation.sql`など）が追加された場合は、そのファイルだけを追加で実行すればよい（`schema.sql`を再実行する必要はない）。`supabase/`フォルダ内の`migration_*.sql`は、追加された順に一度ずつ実行していく想定。

### 3-3. メール確認なしでテストユーザーを作成する

1. Supabaseダッシュボード → **Authentication** → **Users** → **Add user** → **Create new user**
2. メールアドレス・パスワードを入力し、「Auto confirm user?」をONにする
3. 作成後、アプリのログイン画面からそのままログイン可能（確認メール不要）

### 3-4. メール送信に関する既知の制限

- Supabaseの標準メール送信（組み込みSMTP）は送信数のレート制限が厳しい（無料プランで1時間あたり数通程度）
- 確認メールの件名・本文（テンプレート）を編集するには、カスタムSMTP（Resendなど）の設定が必須（未設定の場合はダッシュボードのテンプレート編集画面で警告が表示され編集できない）
- 複数の実在ユーザーへメールを送る本番運用を行う場合は、事前にカスタムSMTP＋送信ドメイン認証の設定を推奨

## 4. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 新規登録で「email rate limit exceeded」と表示される | Supabase組み込みメール送信のレート制限に達した | 1時間程度待って再試行するか、3-3の手順でユーザーを直接作成する |
| 登録したのにログインできない | メール確認が完了していない | 届いたメールのリンクをクリックする。またはSupabaseダッシュボードから該当ユーザーの確認状態を手動で変更する |
| マイページに「管理画面へ」が出ない | `is_admin`が`false`のまま | 2-1の手順で`is_admin`を`true`に変更し、アプリを再読み込みする |
| おーえん画面に応援したい相手が出てこない | 自分自身は一覧から自動的に除外される仕様 | 別アカウントでログインして確認する |
| プロフィール写真がアップロードできない | ファイルが5MB超、または画像以外の形式 | 5MB以下の画像ファイル（jpg/png等）を選び直す |
