## 3. transactions テーブル

**主キー：** `id`（`gen_random_uuid()`で自動採番）

### カラム定義

| カラム名 | 型 | 必須 | 説明 | 例 |
|---|---|---|---|---|
| id | uuid | ✅ | 取引ID | 自動生成 |
| from_user_id | uuid | ✅ | 支払い者（`profiles.id`参照） | |
| to_user_id | uuid | ✅ | 受け取り者（`profiles.id`参照） | |
| menu_name | text | ✅ | 選択したメニューのサマリー文字列 | "手びねり体験（60分）" |
| items | jsonb | ✅ | 明細（下記参照） | |
| price | integer | ✅ | 定価合計（円） | 5000 |
| paid | integer | ✅ | 支払い合計（円・price以上） | 7000 |
| op | integer | ✅ | 付与OP（`greatest(paid - price, 0)`。`status`が`received`になるまでは`profiles.op`にはまだ反映されない） | 2000 |
| message | text | | 任意メッセージ | |
| status | text | ✅ | `pending`（確認待ち）／`received`（受取済）。初期値`pending` | "pending" |
| confirmed_at | timestamptz | | 受け取り側が確認した日時 | |
| created_at | timestamptz | ✅ | 取引作成日時（自動） | |

### items カラム（jsonb配列の要素）

```json
{ "name": "手びねり体験（60分）", "price": 5000, "quantity": 1, "paid": 7000 }
```

> 旧設計にあった`fromUserName`/`toUserName`の非正規化フィールドは持たない。表示時に`profiles`とのJOINで名前を解決する。
> `status`は`pending`／`received`の2値。支払う側の自己申告額だけでOPが加算されることを防ぐため、受け取る側が`confirm_ouen_transaction()`を呼んで確認するまでOPは加算されない（6章参照）。

## 5. Row Level Security（RLS）

`profiles`と`transactions`は共にRLSを有効化。

```sql
-- 管理者判定ヘルパー
create or replace function public.is_admin() returns boolean
language sql stable security definer set search_path = public as $$
  select coalesce((select is_admin from public.profiles where id = auth.uid()), false);
$$;

-- profiles
create policy "profiles_select_all" on public.profiles
  for select to authenticated using (true);
create policy "profiles_insert_self" on public.profiles
  for insert to authenticated with check (id = auth.uid());
create policy "profiles_update_self_or_admin" on public.profiles
  for update to authenticated
  using (id = auth.uid() or is_admin())
  with check (id = auth.uid() or is_admin());

-- transactions（直接INSERTポリシーは無し。書き込みはRPC経由のみ）
create policy "transactions_select_all" on public.transactions
  for select to authenticated using (true);
create policy "transactions_delete_admin" on public.transactions
  for delete to authenticated using (is_admin());
```

## 6. 取引作成・OP加算用RPC関数

取引の作成と、確認後のOP加算はクライアントからの直接updateではなく、以下2つのPostgres関数（SECURITY DEFINER）で行う。支払う側の自己申告額だけでOPが増えることを防ぐため、insert時点ではOPを加算せず、受け取る側が別途確認して初めて加算する2段階構成になっている。

### create_ouen_transaction — 取引を`pending`（確認待ち）として作成

```sql
create or replace function public.create_ouen_transaction(
  p_to_user_id uuid, p_menu_name text, p_items jsonb,
  p_price integer, p_paid integer, p_message text
) returns public.transactions
language plpgsql security definer set search_path = public as $$
declare
  v_op integer := greatest(p_paid - p_price, 0);
  v_tx public.transactions;
begin
  if auth.uid() is null then raise exception 'not authenticated'; end if;
  insert into public.transactions
    (from_user_id, to_user_id, menu_name, items, price, paid, op, message, status)
  values
    (auth.uid(), p_to_user_id, p_menu_name, p_items, p_price, p_paid, v_op, p_message, 'pending')
  returning * into v_tx;
  return v_tx;
end;
$$;
```

### confirm_ouen_transaction — 受け取る側が確認し、OPを加算

```sql
create or replace function public.confirm_ouen_transaction(p_transaction_id uuid)
returns public.transactions
language plpgsql security definer set search_path = public as $$
declare
  v_tx public.transactions;
begin
  if auth.uid() is null then raise exception 'not authenticated'; end if;
  select * into v_tx from public.transactions where id = p_transaction_id;
  if v_tx is null then raise exception 'transaction not found'; end if;
  if v_tx.to_user_id != auth.uid() then raise exception 'not authorized'; end if;
  if v_tx.status != 'pending' then raise exception 'transaction is not pending'; end if;

  update public.transactions set status = 'received', confirmed_at = now()
    where id = p_transaction_id returning * into v_tx;

  if v_tx.op > 0 then
    update public.profiles set op = op + v_tx.op where id = v_tx.to_user_id;
  end if;
  return v_tx;
end;
$$;
```

`to_user_id != auth.uid()`と`status != 'pending'`のチェックにより、本人以外による確認や、二重確認によるOPの二重加算を防いでいる。

| バケット名 | `avatars` |

## 8. 旧設計（Firestore版）との主な差分

| 項目 | 旧（Firestore） | 新（Supabase/Postgres） |
|---|---|---|
| ユーザーID | Firebase Auth uid | Supabase Auth uid（`auth.users.id`） |
| 認証方式 | 電話番号（SMS） | メールアドレス＋パスワード |
| users→profiles | phone必須、photoURL未使用 | phoneカラム無し、avatar_url実装済み |
| transactions.status | pending/approved/rejectedで承認制 | pending/receivedの2値。受け取る側の確認でOP加算（拒否機能は無し） |
| 名前の非正規化 | fromUserName/toUserNameを保存 | 保存せず、表示時にJOINで解決 |
| OP加算方法 | クライアントから相手ドキュメントを直接update | DB関数（RPC）でアトミックに実行 |
| アクセス制御 | Firestore Security Rules | Postgres Row Level Security |
